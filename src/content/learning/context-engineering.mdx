上下文工程关注每一次推理时，模型实际看到了什么：任务、指令、示例、历史、工具定义、检索结果与外部资料。它包含提示词的组织，也包含后续不断选择、读取、压缩和更新信息的过程。

对个人学习而言，可以先从一份简单清单开始：**目标 → 硬约束 → 相关原文与来源 → 已作决定 → 未知项 → 验收问题**。资料存进笔记库，并不等于本次回答已经使用它；资料写得再多，也不能代替核验。

## 学习路径

先看任务与指令边界，再看资料选择、版本和冲突，最后处理预算、压缩、外部记忆与评测。地图连线表达概念分组和关联，不是系统执行顺序。

任务约定应明确要解决的问题、输出要求和不确定时怎样处理。资料保留来源、适用范围、更新时间及原文定位。版本判断不能只按日期排序：要看权威性、替代关系和实际证据。两份无法消解的记录互相矛盾时，应保留冲突并核实，而不是任选一句。

## 给博客助手准备资料

实验中的 A–G 都是虚构材料，不代表本站的技术决定或部署状态。你可以选择技术栈或发布状态问题，再选择资料与预算，预测结果后查看依据和本次上下文清单。

- A 是当前计划，明确替代 B；B 只能解释旧计划，不能证明现行决定。
- C 是 A 的有损摘要：保留技术栈，遗漏“不引入 LangChain”的约束。
- D 与 E 是同时间、同等级但相互矛盾的未核实记录。单份只能支持“该记录声称”，两份并存需要核对部署 ID 与线上状态。
- F 是无关资料；G 是外部评论中的指令，既不构成证据，也不构成授权。

预算使用人为指定的格数：任务 2 格，输出预留 1 格，其余为卡片占用。它不是 tokenizer、真实 token 计数或价格估算。超过预算时实验阻止提交，不自动截断；模型服务的实际超限行为应按具体接口确认。

实验仅按卡片 ID 和预先标注的属性运行固定 TypeScript 规则，不理解自然语言，不进行检索、摘要生成、事实查证或注入检测，也不会调用真实模型。结果用于练习证据判断，不是模型能力或安全性的测量。无关资料只影响预算，不模拟模型注意力；分区标签也不是安全隔离机制。

## 把它用于自己的数字化学习

先整理一个正在学习的问题，放入必要原文和你的约束。资料多了之后，用目录、标题、路径和搜索逐步展开，不必先建复杂的 Agent 系统。纯 TypeScript 与现有文件读取、查询工具就能开始。

需要跨会话继续时，保存目标、关键决定、未完成项和来源定位。将明确偏好与临时假设分开，给笔记标注更新时间与适用范围。压缩后逐条检查硬约束，有疑问时回读原文。长期记忆需要实际保存和再次读取，它不会自动变成模型参数。

最后用一组固定问题对比改动前后：回答是否被证据支持、引用是否真的支持结论、关键约束有没有丢失、缺证据时是否限定回答，以及成本和延迟是否可接受。一次只改变一个因素，避免把检索、提示和模型同时改动后的结果归因于单个技巧。

理解检查中的文字只在当前视图保留，切换学习方式、刷新或离开会清空；可展开 Markdown 笔记自行复制保存。

## 调研与参考

以下资料于 **2026-11-11** 查阅。通用实践与本实验的具体规则分别说明，资料中产品相关的历史功能不作为当前 API 保证。

- [Anthropic：Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)，2025-09-29：上下文的持续维护、最小充分信息、按需检索、压缩与外部笔记。实验中的卡片、格数和版本判定是为学习设计的规则，并非该文章提出的标准算法。
- [OWASP：LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)：外部内容可影响模型行为；RAG 或微调不能完全消除注入风险。清晰区分数据与指令，并由应用执行最小权限与输出验证。
- [Liu 等：Lost in the Middle](https://arxiv.org/abs/2307.03172)，2023：查阅论文摘要与版本信息；其多文档问答和键值检索实验发现相关信息位置会影响所测模型表现。这是历史实验结论，不意味着所有当前模型都有相同退化程度或统一的最佳排序方式，应在自己的任务上验证。
