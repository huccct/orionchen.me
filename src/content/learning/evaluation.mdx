评测回答“改动之后是否更好”，可观测性帮助定位“为什么变好或变差”。本专题包含四个领域、十个概念，以及一组可复核的对比实验。

## 从哪里开始

沿 **成功标准 → 代表样例 → 确定性校验 → 分组结果 → 延迟与用量 → 回归门槛** 探索。地图连线表示知识分组与关联，不是请求执行顺序。人工标注、模型裁判、留出集和诊断日志提供概念与练习，本页没有接入生产观测平台。

## 对比实验

任务是从虚构商品政策中提取退货天数，输出仅含 days 字段的 JSON 对象。天数为非负安全整数；未提供期限时为 null。四条人工标注包含两条常规题、例外条款和缺失信息。

先查看 A / B 提示词和参考答案，再选择样本组、评分规则，预测哪版通过率更高。运行后复核每题输出，并比较平均首段延迟、平均完整响应耗时和累计输入 / 输出 Token。

- 全部样例只看结构：A 为 4/4，B 为 3/4。
- 同时要求结构和答案正确：A 为 2/4，B 为 3/4。
- 只看常规题的联合通过率：A 为 2/2，B 为 1/2。总体胜出仍可能掩盖分组退化。

“14天”虽然人能读懂，但不满足 JSON 接口约定。格式正确的 14 也可能遗漏 30 天的例外条款。这里的联合通过率是 **结构合规且值等于参考值**，不是对自由文本语义的评分。

**输出、耗时和 Token 都是人工固定的教学记录**，不是提示词生成或真实 API 测量。评分、过滤和聚合由 TypeScript 实时执行。假设同一模型与配置、每题每版一次、请求完整结束、无缓存及重试；仅靠提示词约定 JSON，未使用 API 结构化输出。B 的格式错误不代表结构化输出失效。

这些公开题属于教学 / 开发集，不是独立测试集；不能用四题单次结果证明模型优劣、泛化或统计显著性。真实比较应保留独立样本，重复运行，报告分母和分组退化。本页不进行真实计费估算，Token 总量不能代替账单。

切换条件清空预测，切换学习方式或刷新清空实验。书面回答仅保留在当前理解检查视图，离开即清空，不上传、不保存、不自动评分。

## 接回 TypeScript 项目

先用一个 TypeScript 脚本读取版本化样例，通过官方 SDK 保存模型输出、状态、耗时与 usage，再执行确定性校验和必要的人工评审。无需 LangChain，也不必先搭建观测平台。

日志以应用 trace ID 关联各阶段，记录提示词、模型、数据和评分器版本。避免默认保存完整私有输入和密钥；为确需保留的内容设置脱敏、访问限制与保留期限。真实成本需按模型当期价格、输入输出与适用的缓存读写分别核算，并考虑重试和工具费用。

先修复本实验的格式退化，再用独立样例验证，而不是把一次总体胜出直接当成发布许可。
