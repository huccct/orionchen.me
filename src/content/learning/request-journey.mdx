服务端正在生成内容，页面却一动不动，最后突然出现整段回答。这个现象可能发生在上游、服务端、代理或浏览器，不能只凭“页面卡住了”判断原因。

## 沿着一条链路探索

连接与请求 → 服务端生成 → SSE 事件 → 代理转发 → 浏览器读取 → React 提交。地图连线表示概念分组，实验步骤才表示本例的时间顺序。

先展开「代理与缓冲」和「浏览器与界面」。检查服务端是否增量写出、代理是否暂存、客户端是否等待完整正文，以及收到事件后是否及时更新界面。

## 同样的回答，不同的等待

流式实验固定为三段文本，提供实时传输、代理缓冲和客户端断开三种场景。代理场景特意模拟“攒到结束才发送”；断开场景发生在第一段显示后，还可切换服务端是否将取消传给上游。

先预测最终页面，再逐步比较服务端已生成、代理尚未发送、浏览器已接收和用户当前看到的文本。最终结果相同，也可能有完全不同的首段等待时间；客户端停了，上游也可能仍在运行。

实验不发起真实请求，不调用 AI，不测量网络或推理性能。它把解码、事件解析与界面提交合并为一步；真实网络块不等于 SSE 事件，事件不等于模型 token，React 提交也不等于浏览器立即绘制。取消传播在模型中即时生效，实际需要处理传播延迟、竞态和不支持取消的上游。离开实验或刷新后，预测与步骤清空。
