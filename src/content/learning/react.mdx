React 解决的是：当数据变化时，怎样用组件描述并更新界面。先理解数据流和渲染过程，再按需要学习 API。

## 建议的探索顺序

组件与 JSX → Props 与组合 → State 与事件 → 渲染与状态快照，然后理解 Effect 与状态共享。地图的连线表示概念联系，不是执行顺序；实验时间线才表示一次更新的阶段。

## 从基础到工程的完整路径

地图按领域、子主题、概念逐层展开，初始折叠不表示内容缺失。先看语言与平台、组件、数据流和状态，再进入 Hook、表单、异步并发与服务端边界；性能、可访问性、测试与应用架构贯穿项目实践。

每个概念包含用途、场景、误区、练习目标和官方资料。**概念说明与交互实验分开标注**：当前有状态更新实验，其余节点提供可执行的练习目标，不会假装已有专项实验。生态节点用于区分 React 核心、浏览器和框架的职责。

以 React 19.2 项目环境为起点，当前官方参考可能含更高版本或 Canary 能力，使用前应核对版本与发布通道。地图覆盖主要知识领域，不把历史兼容 API、所有第三方库或未来新 API 声称为已经穷尽。

## 实验的边界

渲染实验是可以逐步查看的教学模型，不是 React 内部调度器的实时追踪。固定初始 count 为 0，模拟同一个同步点击事件里的三次更新，不包含并发中断、Suspense、服务端组件或 flushSync。

React 可以批量处理更新；一次渲染也可能被中断或放弃。开发模式的 Strict Mode 可以额外调用组件和更新函数。因此不要把本实验的四个阶段理解为固定的函数调用次数，也不要用它测量性能。

示例代码仅展示核心片段，省略导入和周边组件。理解检查的文字仅在当前练习视图中保留，切换视图、刷新或离开后清空，不上传、不持久化，也不自动评分。
