这张地图服务于自己的日常开发：让 AI 帮你搜索、实现与检查，同时保留你对需求、证据和取舍的判断。五个领域、十个概念，对应一次改动的完整过程。

## 从哪里开始

沿 **目标与完成条件 → 真实代码路径 → 项目规则 → 读 diff → 验证证据 → 留下理解** 探索。地图连线是知识分组与关联，不是工具执行顺序。

复杂或模糊任务先调查与规划；简单明确的改动可以直接实现。每一步都围绕实际问题，不要求固定的长提示词，也不需要先安装一套 Agent 框架。

## 审查练习：博客的双语入口

本站知识地图列表在英文内容为空时，会展示中文内容。页面语言 locale 和卡片内容语言 topic.lang 可能不同，卡片链接应采用内容语言。

练习假设正在给卡片添加详情导航。需求包含中文入口、英文回退、英文译文、键盘操作、移动布局和构建验证。先读三份候选 diff 与提交者的验证记录，选择“需要修改代码”“需要补充验证”或“本题范围内可接受”，并写一句依据，再查看反例。

- **候选 A**：用页面语言拼接链接；英文回退中文时会指向错误路径。
- **候选 B**：使用内容语言，但只给出中文常规用例，缺少其他验收证据。
- **候选 C**：逻辑和本题的预设验证记录均覆盖要求，可在限定范围内接受，不代表整个网站无缺陷或自动获准发布。

背景来自本仓库的 `LearningIndexContent` 和 `getLearningTopics`。其中“没有英文内容就展示中文”的行为是真实的；候选 diff、报告和故障均为**教学改写**，不是真实历史提交或 CI 输出。英文译文用例也是虚构条件，不表示线上已有译文。

点击检查后，TypeScript 只推导固定片段的 URL 并比对预期，不执行任意代码、不访问生成的地址、不运行项目测试，也不调用 AI。推导通过不替代浏览器与构建检查。参考判断是本题设定的反馈，不会自动评判你的书面推理或认证学习掌握程度。

## 用在下一次自己的改动

一个可以直接改写的任务约定：

> 给知识地图卡片增加可访问的详情导航。先检查列表的数据来源和语言回退规则，复用项目现有组件。中文内容打开中文原文，英文译文打开英文详情。验证英文页面回退中文的情况、键盘激活和窄屏布局，运行相关检查。汇报改动、验证证据和仍未覆盖的范围。

遇到问题时，把“还是不对”改成具体反馈：触发条件、预期、实际、证据，以及期望如何复验。让 AI 调查尚未确认的怀疑，不要把猜测当成结论。

本仓库 `AGENTS.md` 要求先看安装版本的 Next.js 文档，就是可复用的项目约束。稳定且反复出现的经验可以沉淀到项目规则；可重复的完整流程再考虑整理为 Skill。不要仅因为工具支持就增加依赖或自动化。

## 留下自己的理解

在“理解检查”里写下自己的解释、依据与下一步问题，可以展开 Markdown 笔记，全选复制到你自己的知识库。当前版本不提供账户、云同步或自动持久化。

审查练习在换候选、重新练习、切换学习方式或刷新时清空；理解检查文字在离开视图或刷新时清空。两处输入都不上传、不自动保存、不自动评分；需要保留的理解请先复制导出。

可结合 [大模型基础与接入](/learning/llm) 理解工具边界，用 [模型评测与可观测性](/learning/evaluation) 练习判断证据，再到 [AI 应用与 Agent 工程](/learning/agent-engineering) 理解权限与执行结果。
