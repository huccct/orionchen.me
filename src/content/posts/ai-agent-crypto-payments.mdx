## 一、问题不是 Agent 有没有钱包

当 AI Agent 开始替人订票、购买软件服务，甚至调用另一个 Agent 完成任务，一个很自然的问题出现了：它该怎么付钱？

我最初的答案很直接。传统金融要求身份、账户和人工确认，Crypto 原生支持程序调用、实时结算和小额交易，所以 Agent Economy 最终只能建立在 Crypto 之上。

重新看了一遍正在形成的支付协议后，我发现这个判断把两件事混在了一起：**谁有权花钱，以及钱最终通过什么方式结算。**

Agent 通常不是财产的所有者，也不需要成为独立的法律主体。它更像一个被委托的执行者：在某个时间内，替一个人或组织，向被允许的商户支付不超过某个限额的钱。

因此，真正困难的不是给 Agent 一个钱包，而是把授权说清楚。

## 二、一笔 Agent 支付至少有三层

国际货币基金组织在讨论 Agent 支付时，把问题拆成了意图、授权与结算三层。这个划分比“银行卡还是 Crypto”更接近问题本身。

| 层次 | 需要回答的问题 | 可能的实现 |
| --- | --- | --- |
| 意图 | 用户到底想买什么，允许 Agent 自主到什么程度 | 自然语言指令、商品与价格约束 |
| 授权 | 谁同意这笔交易，限额、期限和责任是什么 | 签名委托、支付令牌、人工确认 |
| 结算 | 价值最后如何转移 | 银行卡、银行转账、平台余额、稳定币 |

大语言模型的输出带有概率性，支付执行却必须是确定的。“帮我订一张合适的机票”可以交给模型理解，但扣多少钱、付给谁、能否退款，不能只靠模型临场判断。

Agent 支付最重要的基础设施，可能不是一条更快的链，而是一份机器能够验证的委托书。

## 三、传统支付并没有失去资格

银行卡和银行账户确实不是为自主软件设计的。它们存在固定手续费、跨境摩擦和身份门槛，对几分钱一次的 API 调用尤其不友好。

但这不等于 Agent 必须自己开户。Visa 的 Trusted Agent Protocol、Google 的 Agent Payments Protocol，以及 Stripe 的 Shared Payment Tokens，都在尝试让 Agent 携带可验证的用户授权，在现有支付网络里完成交易。Agent 拿到的不是完整卡号，而是用途、商户和金额受到限制的凭证。

这条路线有一个明显优势：商户覆盖、退款、争议处理和合规体系已经存在。对于订酒店、买商品这类消费者交易，重新利用现有网络，可能比要求所有人先准备链上钱包更现实。

传统支付的问题可以通过新的协议层缓解，而不是只有推倒重来一种答案。

## 四、Crypto 真正有优势的地方

Crypto 仍然很适合一部分 Agent 支付，只是它的优势没有覆盖所有场景。

Coinbase 推动的 x402 协议，把支付要求放进 HTTP 请求与响应中。一个 Agent 调用付费 API 时，可以在程序里发现价格、支付稳定币并继续请求，不必先注册账户、购买套餐或等待人工开通。对于机器对机器的小额、高频调用，这种体验很有吸引力。

稳定币也提供了全天候、可编程和跨境结算的可能。但“链上”并不自动等于便宜、安全或全球无障碍。网络费用、托管风险、私钥管理、稳定币脱锚、隐私与不同地区的监管要求仍然存在。

更实际的比较是：

| 结算方式 | 更擅长的场景 | 主要代价 |
| --- | --- | --- |
| 令牌化银行卡或银行支付 | 消费者购买、退款与争议处理 | 小额支付和跨境交易仍有摩擦 |
| 稳定币与链上支付 | API 微支付、全天候机器结算 | 托管、合规、隐私和链上风险 |
| 平台内部余额 | 同一市场里的高频交易 | 形成封闭生态，跨平台能力弱 |

Stripe 的 Machine Payments Protocol 同时支持稳定币和共享支付令牌，也说明未来更可能是协议统一意图与授权，底层允许多种结算方式竞争。

## 五、比支付速度更重要的约束

如果要让 Agent 真正替我花钱，我更关心下面这些问题：

- 它最多能花多少，多久以后授权自动失效；
- 它只能购买哪类商品，能否向新商户付款；
- 超过什么金额必须再次询问我；
- 每笔交易能否留下可核验的订单、授权和执行记录；
- 我能否随时撤销权限，出错后由谁退款和承担责任；
- 模型负责提出交易以后，能否由确定性程序检查并执行。

这些限制对银行卡、稳定币和平台余额都适用。没有它们，再快的结算也只是让错误更快发生。

## 六、我的判断

我仍然认为 Crypto 会成为 Agent Economy 的重要组成部分，尤其适合无账户的机器服务、API 微支付和跨境结算。但它不是 Agent 支付的唯一答案，更不能替代授权、责任与风控。

未来的 Agent 也许可以同时使用银行卡令牌和稳定币，就像今天的软件同时调用数据库、云服务与第三方 API。用户不需要关心每一笔交易走哪条轨道，只需要知道 Agent 在什么范围内代表自己行动。

所以，Agent 支付真正要解决的不是“怎样让 AI 拥有钱”，而是：**怎样让一台不确定的机器，在一套确定、有限并且可追责的权限里使用人的钱。**
